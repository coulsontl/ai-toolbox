# 会话列表性能验证（Issue #344）

本轮将共享会话列表接入单列虚拟网格，隔离输入与卡片渲染，并用集合查询选择状态。完整会话结果仍保存在面板中；搜索、计数、选择已加载和批量操作继续针对完整过滤结果。

- 问题：https://github.com/coulsontl/ai-toolbox/issues/344
- 测试日期：2026-09-12（Asia/Shanghai）。
- 修改前基线：`1afc6473` 的 `SessionManagerPanel.tsx` 与对应样式。
- 实现入口：`web/features/coding/shared/sessionManager/SessionList.tsx`。

## 方法与边界

- 环境：Windows，AMD Ryzen 7 9700X 8-Core Processor，Edg/134.0.3124.93（headless），Node v22.20.0。
- 使用 Vite production build 和 React profiling build，挂载真实 `SessionManagerPanel`、`VirtualGrid` 与 `KeepAliveOutlet`。
- 使用相同的合成 `SessionMeta` 数据和内存 Tauri API。不会读取、删除或修改真实 CLI 会话，也不会改写系统剪贴板。
- 固定测试视口为 1280 × 900；另外在 600 × 800 下验证长路径换行和变高行。
- 每轮分别启动修改前、修改后的独立浏览器，按 500、2000、5000 条会话顺序测试；共 3 轮、18 份样本。下表使用各组中位数，未混入调试中断的轮次。
- 500 条是每个浏览器实例的首个场景，后两组是同一实例内的后续导航。因此跨规模数值也受浏览器预热影响，应比较同一行的修改前后结果。
- “首屏 React 渲染”是首屏期间 Profiler 记录的面板渲染时间之和；“数据就绪到绘制”从模拟 API 返回到连续两次 requestAnimationFrame 后采样。
- 输入测试写入一个空格，使受控输入框更新、但不改变 trim 后的查询条件，以隔离输入引发的渲染成本。“全选响应”同样使用事件到连续两帧后的时间。
- 这些数据衡量前端列表渲染，不包含 Rust 会话扫描、真实文件 I/O、WSL/网络延迟或完整桌面应用启动。后端已有的元数据缓存与详情查找路径未在本轮改造。

## 结果

表中的箭头表示修改前 → 修改后。

| 会话数 | 首屏挂载卡片 | 首屏文档元素数 | 滚动期间最大挂载卡片 |
| ---: | ---: | ---: | ---: |
| 500 | 500 → 14 | 15,120 → 555 | 500 → 20 |
| 2,000 | 2,000 → 14 | 60,120 → 555 | 2,000 → 20 |
| 5,000 | 5,000 → 14 | 150,120 → 555 | 5,000 → 20 |

| 会话数 | 首屏 React 渲染 ms | 数据就绪到绘制 ms | 输入 React 渲染 ms | 全选响应 ms |
| ---: | ---: | ---: | ---: | ---: |
| 500 | 119.9 → 45.3 | 268.1 → 112.2 | 50.7 → 1 | 191.3 → 14.1 |
| 2,000 | 320.2 → 23.9 | 918.8 → 25.1 | 204.3 → 1.2 | 791.2 → 9.9 |
| 5,000 | 844.7 → 33.5 | 2,425.6 → 32.4 | 496 → 1 | 2,010 → 12.5 |

在这组测试中，5,000 条会话的首屏 React 渲染时间下降约 96.0%，文档元素数从 150,120 降至 555。卡片挂载数量由视口与 overscan 决定，不再随完整会话数量线性增长。

脚本还记录了 120 帧程序化滚动采样：5,000 条场景的 rAF 平均帧率中位数为 13.7 → 57.4，P95 帧间隔为 111.1 → 23.2ms。headless 的帧调度不等同于真实屏幕或 Tauri WebView，因此这组数值只用于同环境对照，不能作为真实桌面 FPS 的保证。

## 交互回归与自审

浏览器回归共 30 项，全部通过，覆盖：

- 5,000 条完整列表的虚拟挂载、滚动到底和全选范围；滚出视口再返回时保留选择。
- 精确会话 ID、无结果搜索、搜索后清理旧选择、本机/WSL 来源切换，以及完整快照复用。
- 深处进入详情后的滚动恢复、KeepAlive 隐藏后再显示。
- 上方配置区收起、列表整体位置变化但没有滚动事件时，立即重算可见范围。
- 批量删除部分失败后，刷新真实列表并仅保留失败项的选择。
- Resume 命令复制、禁用状态、标题键盘聚焦与 Enter 打开详情。
- 长路径变高行、窄视口、行间不重叠、亮色/暗色/system theme。
- Codex 与 OpenCode 两个消费入口，以及 recent 快照到后台 full 结果的替换。

自审发现并修复：共享 `VirtualGrid` 在 KeepAlive 隐藏页中可能把 `offsetHeight=0` 写入行高缓存，导致返回深处滚动位置时空白。现已忽略零行高，保留最后一次可见测量；同一浏览器回归在修复前失败、修复后通过。

二次审查补充复现并修复：上方配置区收起会改变列表位置，但虚拟网格自身宽高和 `scrollTop` 可以保持不变。原监听遗漏这种变化，导致进入视口后仍只挂载首行。现在沿网格到 `main` 的布局链监听尺寸变化并更新偏移；新增的无滚动布局变化回归在修复前失败、修复后通过。本文性能结果已用最终实现重新完成三轮对照。

同时核对了列表/卡片的 memo 边界和回调依赖、`sourcePath` 身份、完整结果上的批量选择、后台刷新后的选择清理，以及现有 full/cache-first、导入删除刷新和导航契约。最终自审未发现本轮变更中仍需修复的问题。

验证结果：

- `pnpm test`：536 项通过，0 失败、0 跳过。
- `pnpm exec tsc --noEmit`：通过。
- `pnpm build`：通过；有构建产物 chunk 大于 500KB 的提示。
- `node scripts/benchmark-session-list.mjs --baseline 1afc6473 --repetitions 3`：退出码 0，18 份性能样本、30 项浏览器检查。
- 发布前另在 `1cafb14b` 的干净检出中仅复制本次 11 个文件验证：536 项前端测试、生产构建及 30 项浏览器检查全部通过，确认本次改动不依赖工作区中的其他未提交功能。
- 本轮未修改 Rust 后端，未运行 Rust 全量测试。

## 复跑

```powershell
# 仅运行浏览器交互回归
node scripts/benchmark-session-list.mjs --verify-only

# 与改造前版本做三轮性能对照
node scripts/benchmark-session-list.mjs --baseline 1afc6473 --repetitions 3
```

需要已安装的 Chrome/Edge；自动发现失败时用 `--browser` 指定可执行文件。可通过 `--output` 指定报告父目录，脚本始终在其中新建独立目录。

脚本会打印 `Artifacts` 和 `Report` 路径，保留完整 `report.json`、浏览器检查列表与三个主题截图。本次完整结果位于临时目录 `session-list-benchmark-QzyEjM`。基线只替换面板及其样式，依赖版本和测试夹具保持一致；工作区不会被 checkout、reset 或覆盖。
